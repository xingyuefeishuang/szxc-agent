# 订单查询接口

## 基础信息
- **接口名称**：订单查询
- **接口地址**：`/QueryOrder.do`
- **请求方式**：POST
- **数据格式**：application/json
- **接口描述**：携程可以根据供应商提供的查询接口获取供应商订单处理的具体状态、使用情况等信息。
  <p style='color: red'>供应商接口返回码：务必优先匹配携程提供的标准错误码，并返回真实的失败原因（重要）。</p>

---

## 请求参数
### 1. 请求参数示例
```json
{
  "header": {
    "accountId": "xiecheng",
    "serviceName": "QueryOrder",
    "requestTime": "2017-01-05 10:00:00",
    "version": "1.0",
    "sign": "374d95774f17c3e354e73f7aaf21b5ec"
  },
  "body": {
    "sequenceId": "2017-10-10abcd95774f17c3e354e73f7aaf21b5ec",
    "otaOrderId": "123456",
    "supplierOrderId": "100001"
  }
}
```

### 2. 请求头 (Headers)

| 参数名称 | 类型 | 必填 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| accountId | string | 是 | 供应商帐号，由携程分配 | xiecheng |
| serviceName | string | 是 | 接口名称: QueryOrder | QueryOrder |
| requestTime | string | 是 | 请求时间(格式: yyyy-MM-dd HH:mm:ss) | 2017-01-05 10:00:00 |
| version | string | 是 | 版本号, 1.0 | 1.0 |
| sign | string | 是 | 签名 | 374d95774f17c3e354e73f7aaf21b5ec |

### 3. 请求体 (Request Body)

**注意：请求体 body 节点在传输时需要 AES 加密。**

#### Body 结构 (加密前)

| 参数名称 | 类型 | 必填 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| sequenceId | string | 是 | 携程处理批次流水号。格式为处理日期（yyyyMMdd）+32位去分隔符的Guid | 2017-10-10abcd95774f17c3e354e73f7aaf21b5ec |
| otaOrderId | string | 是 | 携程订单号 | 123456 |
| supplierOrderId | string | 否 | 供应商订单号 | 100001 |

## 响应结果
### 1. 响应结果示例
```json
{
  "header": {
    "resultCode": "0000",
    "resultMessage": "操作成功"
  },
  "body": {
    "otaOrderId": "12345",
    "supplierOrderId": "100001",
    "items": [
      {
        "itemId": "123456",
        "useStartDate": "2017-02-04",
        "useEndDate": "2017-02-04",
        "orderStatus": 1,
        "quantity": 1,
        "useQuantity": 1,
        "cancelQuantity": 1,
        "passengers": [
          {
            "passengerId": "123456",
            "passengerStatus": 0
          }
        ],
        "vouchers": [
          {
            "voucherId": "123456",
            "voucherStatus": 0
          }
        ]
      }
    ]
  }
}
```

### 2. 响应头 (Response Header)

| 参数名称 | 类型 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- |
| resultCode | string | 处理结果返回码, 参考: [供应商接口返回码](#section/供应商接口返回码) | 0000 |
| resultMessage | string | 处理结果返回信息。若返回结果为失败，需在此字段内明确描述失败原因。参考: [供应商接口返回码](#section/供应商接口返回码) | 操作成功 |

### 3. 响应体 (Response Body)

**注意：响应体 body 节点在传输时需要 AES 加密。**

#### Body 结构 (加密前)

| 参数名称 | 类型 | 必填 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| otaOrderId | string | 是 | 携程订单号 | 12345 |
| supplierOrderId | string | 是 | 供应商订单号 | 100001 |
| items | array | 是 | 订单项节点 (见 QueryOrderResponseItems 数组定义) | (见 QueryOrderResponseItems 定义) |

#### QueryOrderResponseItems (订单项) 对象定义

| 参数名称 | 类型 | 必填 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| itemId | string | 是 | 订单项编号。如果为空（调用了预下单创建接口，但是没有调用预下单支付接口），该字段必需传0 | 123456 |
| useStartDate | string | 否 | 实际使用开始日期，格式：“yyyy-MM-dd” | 2017-02-04 |
| useEndDate | string | 否 | 实际使用结束日期，格式：“yyyy-MM-dd” 如只有一天将与useStartDate值相同 | 2017-02-04 |
| orderStatus | integer | 是 | 订单状态（见[附录](#section/订单状态)） | 1 |
| quantity | integer | 是 | 订单总份数 | 1 |
| useQuantity | integer | 是 | 实际使用总份数 | 1 |
| cancelQuantity | integer | 是 | 实际取消总份数 | 1 |
| passengers | array | 否 | 出行人节点，cancelQuantity不为0且退订时cancelType=2必传，传全部出行人信息 (见 Passengers 定义) | (见 Passengers 定义) |
| vouchers | array | 否 | 凭证节点，传全部凭证信息 (见 Vouchers 定义) | (见 Vouchers 定义) |

#### Passengers (出行人) 对象定义

| 参数名称 | 类型 | 必填 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| passengerId | string | 是 | 出行人编号 | 123456 |
| passengerStatus | integer | 是 | 0、待使用；1、已使用；2、已取消 | 0 |

#### Vouchers (凭证) 对象定义

| 参数名称 | 类型 | 必填 | 说明 | 示例值 |
| :--- | :--- | :--- | :--- | :--- |
| voucherId | string | 是 | 凭证编号 | 123456 |
| voucherStatus | integer | 是 | 0、待使用；1、已使用；2、已取消 | 0 |
